\subsection{Optimizer comparison protocol}
\label{sec:optimizer-comparison}

The optimizer comparison uses Model~B under three configurations: Adam with
$\alpha=10^{-3}$, plain stochastic gradient descent (SGD) with
$\alpha=10^{-2}$, and SGD with the same learning rate and momentum $m=0.9$.
Only the optimizer block changes; the model, split manifest, random seed, data
order, batch size, augmentation, epoch budget, and execution device are held
constant.  This isolation is checked programmatically before training begins.

The SGD update is
\begin{equation}
  w \leftarrow w-\alpha\frac{\partial L(w)}{\partial w},
\end{equation}
while momentum adds a velocity term,
\begin{equation}
  v \leftarrow mv-\alpha\frac{\partial L(w)}{\partial w},
  \qquad w \leftarrow w+v.
\end{equation}
The momentum value $0.9$ is therefore compared against $m=0$ without changing
SGD's learning rate.

Neither learning rate was tuned for this problem. Adam uses
$\alpha=10^{-3}$, the default recommended by its authors, who note that its
hyper-parameters typically require little tuning~\cite{kingma2015adam}. SGD
uses $\alpha=10^{-2}$, a common starting value. Each optimizer therefore runs
at a setting appropriate to its own family, rather than at one shared
numerical step size that would favour whichever optimizer that value happened
to suit. Comparing several optimizers at their default settings, instead of
tuning the hyperparameters of a single one, is supported by a large benchmark
of deep-learning optimizers, which found the two approaches to perform
approximately equally well~\cite{schmidt2021descending}. The comparison is
accordingly one of each optimizer at a standard setting, not at its
individually tuned best. That qualification matters most for plain SGD:
unlike Adam, it applies one global step size to every parameter, with no
per-parameter adaptation, so its best learning rate depends more strongly on
the problem. Every value is recorded in the resolved configuration of each
run.

Adam at $\alpha=10^{-3}$ is selected for the final custom-model runs.  As shown
in Table~\ref{tab:optimizer-comparison}, it achieved the lowest validation loss
and the highest validation and test accuracy.  Momentum made SGD competitive
by accumulating a velocity that damps oscillation and maintains progress in a
consistent descent direction; plain SGD, at its untuned learning rate,
converged much more slowly within the same 30-epoch budget.  The choice is based on validation loss rather than test
accuracy, so the test split remains an unbiased final evaluation.  Each run
uses the same lowest-validation-loss checkpoint rule, making the comparison
insensitive to a poorer final epoch.

\subsection{Effect of the momentum coefficient}
\label{sec:momentum-ablation}

To isolate the effect of momentum, Model~B was trained with SGD at the fixed
learning rate $\alpha=10^{-2}$ for $m\in\{0,0.5,0.9,0.99\}$.  Every other
resolved setting---including the split, seed, data order, augmentation, batch
size, initialization, and 30-epoch budget---was identical.  All four runs were
also timed on the same NVIDIA GeForce RTX~3060 Laptop GPU, so device variation
cannot explain the differences in Figure~\ref{fig:momentum-ablation}.

The momentum update,
\begin{equation}
  v \leftarrow mv-\alpha\frac{\partial L(w)}{\partial w},
  \qquad w \leftarrow w+v,
  \label{eq:momentum-update}
\end{equation}
shows that $m$ controls how much of the previous velocity survives.  When
successive gradients have a consistent sign, their contributions accumulate
in $v$, increasing progress along that direction.  Across a narrow loss
ravine, gradient components that alternate sign instead cancel part of the
stored velocity, damping side-to-side oscillation while preserving progress
along the ravine.

The curves exhibit both effects.  With $m=0$, Equation~\ref{eq:momentum-update}
has no memory and validation loss remains high within the epoch budget.
Setting $m=0.5$ provides some carry-over and converges faster, but still leaves
substantial loss after 30 epochs.  The $m=0.9$ run descends steadily and reaches
the lowest validation loss, making it the preferred momentum setting under the
fixed budget.  At $m=0.99$, the large retained velocity produces the fastest
initial descent but repeatedly overshoots the local descent direction: the
validation curve oscillates after its early minimum and finishes less stably.
Although that run happens to obtain a slightly higher test accuracy, it is not
selected on the test split; optimizer selection uses validation loss to avoid
biasing the final evaluation.

Thus momentum is not simply ``more is better'': too little fails to exploit
consistent gradients, while too much retains stale velocity and can destabilise
convergence.  For this model and learning rate, $m=0.9$ gives the best balance
between acceleration and damping.
